# Binance Market Data

Сбор market data Binance Futures через WebSocket.

## Инструменты

- BTCUSDT Perpetual

- ETHUSDT Perpetual

## Данные в CSV

Для каждого обновления `bookTicker` в CSV-файл сохраняются следующие поля:

- `event_time_ms` — время события на стороне Binance в миллисекундах.
- `receive_time_ms` — время, когда сообщение было получено программой на компьютере, в миллисекундах.
- `latency_ms` — разница между временем получения сообщения и временем события Binance. Используется как диагностический показатель задержки.
- `transaction_time_ms` — время транзакции, указанное Binance, в миллисекундах.
- `update_id` — уникальный идентификатор обновления market data.
- `symbol` — торговый инструмент, например `BTCUSDT` или `ETHUSDT`.
- `bid_price` — лучшая текущая цена покупки, то есть Best Bid.
- `bid_qty` — объём по лучшей цене покупки.
- `ask_price` — лучшая текущая цена продажи, то есть Best Ask.
- `ask_qty` — объём по лучшей цене продажи.

## Как работает сбор

Используется публичный WebSocket Binance Futures:

- BTCUSDT: `wss://fstream.binance.com/ws/btcusdt@bookTicker`

- ETHUSDT: `wss://fstream.binance.com/ws/ethusdt@bookTicker`

API-ключ для этих публичных market data не требуется.

Данные поступают через WebSocket и складываются в очередь (`queue`). Отдельный поток забирает сообщения из очереди и записывает их в CSV.

Так приём новых WebSocket-сообщений не должен ждать завершения записи на диск.

## Скрипты

- `binance_btc_ws.py` — сбор BTCUSDT Perpetual

- `binance_eth_ws.py` — сбор ETHUSDT Perpetual

Скрипты запускаются отдельно и могут работать одновременно.

## Тестирование

В ходе тестирования:

- вручную сверены best bid / best ask с торговым терминалом Binance;

- проверена запись большого количества обновлений в CSV;

- проверены битые строки;

- проверены полные дубликаты;

- проверены случаи `bid > ask`;

- протестирована очередь записи;

- протестирован одновременный запуск BTC и ETH;

- протестирован reconnect после разрыва WebSocket-соединения.

В тестовом файле BTC было записано около 955 тыс. строк. Битых строк, полных дубликатов и случаев `bid > ask` обнаружено не было.

Очередь записи в основном оставалась пустой и не накапливалась. Наблюдались отдельные всплески latency, которые требуют дополнительного наблюдения при длительном сборе.

## Установка

Для работы скриптов необходим Python 3.

В проекте используются две дополнительные библиотеки:

- `websocket-client`

- `certifi`

Остальные используемые модули входят в стандартную библиотеку Python.

Для установки необходимых библиотек используется команда:

`pip install -r requirements.txt`

## Запуск

Для запуска сбора данных по BTCUSDT Perpetual:

`python3 binance_btc_ws.py`

Для запуска сбора данных по ETHUSDT Perpetual:

`python3 binance_eth_ws.py`

Скрипты можно запускать отдельно или одновременно в двух окнах Terminal.

После успешного подключения в консоли появляется сообщение:

`Connected to Binance Futures`

После этого начинается получение данных и их запись в CSV.

## Остановка

Для остановки работающего скрипта используется сочетание клавиш:

`Control + C`

В текущей версии при остановке во время автоматического переподключения иногда может потребоваться нажать `Control + C` повторно.

## Хранение данных

Поток `bookTicker` достаточно интенсивный, поэтому CSV-файлы быстро увеличиваются в размере.

По этой причине полные файлы с raw market data не загружаются в GitHub. В репозитории хранятся код, документация и небольшие примеры данных.
